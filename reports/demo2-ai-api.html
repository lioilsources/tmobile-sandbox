Jedna GPU, tři zákazníci, jedno API

Tři tenanti sdílejí jeden NVIDIA L40S přes OpenAI‑kompatibilní API s vlastními klíči, limity a účtováním po tokenech. Když dávkový tenant spustil nápor, zákaznický chatbot dál odpovídal do 0,13 s.

133 msprvní token chatbotu (p95) během náporu
~1 000výstupních tokenů za sekundu celkem
16souběžných požadavků, na kterých limit zastavil dávkového tenanta
16,00 Kčvyúčtováno za 6 minut testu (ilustrativní ceník)

Jak to funguje

klient ─► gateway ─► LiteLLM ─► vLLM: chat (Qwen3‑30B‑A3B), embed
           │                  └─► Whisper (přepis řeči)
           ├ API klíč → tenant, povolené modely
           ├ limit souběhu → HTTP 429
           ├ měření tokenů (i ze streamu) a audia
           ├─► kniha pro účtování
           └─► metriky → Prometheus → Grafana

Gateway je brána z AiStacku rozšířená o tenanty, napsaná v Go bez závislostí a pokrytá testy. Klíč tenanta dál neputuje, LiteLLM dostává vlastní master klíč.

Spočítáno z knihy gateway, kde je každý požadavek jedním řádkem. Při tomto provozu to odpovídá zhruba 160 Kč za hodinu na jednu GPU. Předpokládaný náklad VM je asi 55 Kč za hodinu za celý systém, takže tento provoz by při ilustrativním ceníku pokryl náklad zhruba třikrát.

Incident během testu

Při prvním plném běhu se VM jednou tvrdě zastavila a sama nenaběhla. V logu není žádný nedostatek paměti, pád jádra ani chyba GPU. Paměť byla obsazená na 13,5 z 23 GB, GPU mělo 49 °C a 250 W. Opakovaný test se záznamem stavu každé dvě sekundy doběhl bez problému. Příčina je pravděpodobně mimo VM.

Omezení a další kroky

  • Ceník je ilustrativní. Počítáme s předpokládaným nákladem asi 55 Kč za hodinu za celou VM (GPU, 8 vCPU, 23 GB RAM, disky). S větší RAM nebo diskem cena roste.
  • Limit souběhu je jednoduchá pojistka. Pro produkci přidat férové frontování s prioritami a limit na tokeny za minutu.
  • Klíče teď leží v souboru na stroji. Produkce potřebuje správu klíčů s rotací a přístup přes TLS místo SSH tunelu.
  • Rozšíření gateway vrátit do AiStacku.
